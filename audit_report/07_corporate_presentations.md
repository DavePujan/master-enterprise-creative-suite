# Domain 07: Corporate Presentations & Slideshow Engine - Verification Report

## Verification Methodology
- Evaluated `apps/web/src/features/creative/hooks/useCreativeExecution.ts` and `CreativeOutputCanvas.tsx` to assess how presentation data and canvas edits are structured and exported (e.g., `handleDownloadPDF`).
- Investigated `apps/api/src/modules/presentation/renderers/pptxRenderer.ts` to inspect how PPTX files are natively generated from the presentation schemas.
- Reviewed `apps/api/src/modules/presentation/presentationContracts.ts` and `packages/presentation-engine` schemas for provenance tracking and model enforcement.

## Findings Verification

### 1. Canvas Edits Can Be Lost During Export
- **Audit Claim:** Frontend modifications are not always persisted into the canonical presentation document before server-side rendering or export.
- **Status:** **TRUE**
- **Evidence:** The client-side PDF export logic (`handleDownloadPDF` in `useCreativeExecution.ts`) ignores interactive canvas state entirely (e.g., `activeState.textLayers`, styling adjustments). It blindly iterates over the raw, unmodified LLM JSON array (`activeState.result.data`) and renders standard text strings into the PDF. Any visual modifications made in the DOM canvas are lost.

### 2. Slide Count Can Ignore User Intent
- **Audit Claim:** Presentation generation relies on hardcoded planning behavior instead of fully respecting prompt constraints for slide counts.
- **Status:** **TRUE**
- **Evidence:** In `CreativeWorkspace.tsx`, the presentation intent is passed as an unstructured text prompt (e.g., `"Create a 5-slide corporate presentation for..."`) directly into the `generate-content` router rather than strictly enforcing length via a bounded JSON schema block. The model is free to ignore the requested length during freeform generation.

### 3. Invalid Chart Data Can Crash PPTX Rendering
- **Audit Claim:** LLM-produced chart values can contain strings instead of numbers, crashing the PPTX renderer.
- **Status:** **TRUE**
- **Evidence:** `pptxRenderer.ts` blindly maps the generated `chartEl.series` into `values: s.values` and invokes `pptxSlide.addChart`. There is no numeric validation, runtime sanitization, or fallback logic. If the LLM hallucinates string formats (e.g., `"$5M"` or `"N/A"`), it passes the poison payload directly to `pptxgenjs`, resulting in fatal generation crashes.

### 4. Grounding Information Can Be Dropped
- **Audit Claim:** Live-search evidence and citations are not always preserved in the canonical presentation model.
- **Status:** **TRUE**
- **Evidence:** While the intermediate domain models (`MetricData_v1`, `ChartData_v1`) defined in `presentationContracts.ts` correctly implement `provenance` and `source` fields, `pptxRenderer.ts` drops them entirely. The PPTX renderer makes zero references to `provenance` or `source`, meaning that verifiable citations generated by the AI are permanently excluded from the final slide deck.

### 5. Legacy and Canonical Canvas Paths Diverge
- **Audit Claim:** Old DOM controls and the canonical presentation engine expose overlapping or conflicting editing behavior.
- **Status:** **TRUE**
- **Evidence:** The web client operates on a totally parallel state architecture (`textLayers`, generic JSON arrays) that is completely decoupled from the rigorous schema validations and types defined in `@presentation-engine` and `presentationContracts.ts`.
